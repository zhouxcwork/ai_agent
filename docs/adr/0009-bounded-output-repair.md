# 输出修复与重试的有限边界；内容错误不计熔断

---
status: accepted
---

模型输出的 JSON 常被 markdown 包裹或夹杂前后杂文本，直接报错会把可挽救的调用判死。决定在非流式结构化路径引入**有边界的修复链**：先做无损提取修复（markdown 代码块、首尾空白、首 `{` 到尾 `}` 截取），失败后重试上游（默认 2 次，配置化），耗尽即返回明确错误码——绝不静默吞掉、绝不无限重试。关键边界：**内容类错误（invalid_json / schema_validation_failed）不回报熔断器**。理由：JSON 质量是模型内容问题而非路由目标的健康问题，把内容失败计入熔断会让质量差但连接健康的模型被错误摘除；熔断只反映连接/超时类瞬态故障。

## Considered Options

- 不修复，失败即报错（首版行为）：把可挽救的格式噪声判死
- 无限/宽松修复（LLM 二次修复等）：违背"修复要有边界"，成本与延迟不可控
- 有限修复 + 有限重试（选定）：可预期、可配置、失败语义明确
