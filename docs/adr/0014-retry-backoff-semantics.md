# 重试退避语义：retries_per_target 与线性退避

---
status: accepted
---

课程作业要求"指数退避重试（最多 3 次）"。原实现是 `attempts_per_target: 2`（语义=每目标**总尝试**次数，含初次）+ 固定 `sleep(0.1)`——既无退避增长，总尝试也只有 2 次。

## 决策

- **字段改名 `retries_per_target`，语义改为"同目标重试次数"（不含初次）**，默认值 2 不变；总尝试 = 1 + 2 = 3 次，恰好满足作业"最多 3 次"的口径（初次 + 2 次重试）
- **退避间隔线性增长**：`0.1s × 重试序号`（第一次重试前等 0.1s，第二次前等 0.2s），替换原固定 0.1s
- **显式记录与作业字面要求的偏差**：线性 ≠ 指数。取舍：重试次数只有 2 时，线性总等待 0.3s 优于指数（同基数 0.6s），失败路径更快释放目标并发槽位（ADR 0011 快速失败导向）；接受验收时的解释成本
- 重试边界不变：仅 `RetryableUpstreamError` 触发；`UpstreamRejectedError` 直接换候选；流式仅首块前可重试/切换（避免文本重复）；耗尽重试后仍走 fallback 切换下一健康候选

## Considered Options

- 保持 `attempts_per_target` 名字、值改 3、维持"总尝试"语义（否：值 3 与"重试几次"的直觉错位，`- 1` 的边界条件易错）
- 保留旧名改语义（否：名字说 attempts 语义是 retries，名实不符）
- 指数退避满足作业字面（否：见上，等待翻倍对 2 次重试的收益不成比例）

## Consequences

- 默认行为变化：每目标总尝试 2 → 3 次，最坏情况单目标耗时增加约 0.3s；断言尝试次数的测试需同步
- `config.yaml` 键名与注释、README、AGENTS.md 引用点同步更新
- 后续若改主意要指数退避，只需把间隔公式换成 `base * 2 ** retry_number`，无结构性改动（故本 ADR 着重记录"为什么不是指数"）
