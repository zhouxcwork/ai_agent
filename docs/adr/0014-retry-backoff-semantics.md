# 重试退避语义：retries_per_target 与指数退避

---
status: accepted
---

课程作业要求"指数退避重试（最多 3 次）"。原实现是 `attempts_per_target: 2`（语义=每目标**总尝试**次数，含初次）+ 固定 `sleep(0.1)`——既无退避增长，总尝试也只有 2 次。

> 修订记录：本 ADR 初版曾决定线性退避（0.1s/0.2s），后被推翻改为指数——课程验收以字面口径核对，且 0.2s 基数的指数特征可在日志时间戳中直接观察。详见 Considered Options。

## 决策

- **字段改名 `retries_per_target`，语义为"同目标重试次数"（不含初次）**，默认值 2 不变；总尝试 = 1 + 2 = 3 次，满足作业"最多 3 次"的口径（初次 + 2 次重试）
- **退避间隔指数增长**：`0.2s × 2^重试序号`（第一次重试前等 0.2s，第二次前等 0.4s），替换原固定 0.1s
- 重试边界不变：仅 `RetryableUpstreamError` 触发；`UpstreamRejectedError` 直接换候选；流式仅首块前可重试/切换（避免文本重复）；耗尽重试后仍走 fallback 切换下一健康候选

## Considered Options

- 保持 `attempts_per_target` 名字、值改 3、维持"总尝试"语义（否：值 3 与"重试几次"的直觉错位，`- 1` 的边界条件易错）
- 线性退避 `0.1s × n`（初版决策，被推翻）：retries=2 时线性与指数的实际间隔本就相同（0.1/0.2），改指数无行为差异——但 0.2s 基数的指数退避给上游的恢复时间随失败次数放大，工程意义更实，且日志时间戳可直接观察 ×2 递增
- 更大基数或封顶（否：失败路径总等待 0.6s 已够用，两次重试无需 cap）

## Consequences

- 默认行为变化：每目标重试等待从 0.1/0.2s 变为 0.2/0.4s，最坏情况单目标耗时增加约 0.3s；断言尝试次数（3 次）的测试不受影响（无测试断言间隔时长）
- `config.yaml` 键名与注释、README 引用点同步更新
- 后续调整只需改基数（0.2）或指数底（2），无结构性改动
